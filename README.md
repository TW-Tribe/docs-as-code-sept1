# Getting Started: Documentation Practice Project

Welcome to the **Documentation Practice Project**!

This project is designed to help you practice creating and organizing technical documentation using **Markdown and GitHub**.

You will work with a small documentation set that covers the complete user journey, from getting started and installing the product to using, administering, and troubleshooting it.

## Documentation Topics

Explore the documentation using the links below:

1. [Getting Started](docs/getting-started.md)
   Learn what the product does and how to get started.

2. [Installation](docs/installation.md)
   Follow the steps to install and configure the product.

3. [User Guide](docs/user-guide.md)
   Learn how to use the product and perform common tasks.

4. [Administration](docs/administration.md)
   Learn how administrators can manage and configure the product.

5. [Troubleshooting](docs/troubleshooting.md)
   Find solutions to common problems and errors.

## Practice Time

Create the following Markdown files inside the `docs` folder:

```text
docs/
├── getting-started.md
├── installation.md
├── user-guide.md
├── administration.md
└── troubleshooting.md
```

### Your Task

Use these files to practice the Markdown features covered in this workshop.

**Use all the shortcodes/features you have learned**, including:

* Headings
* Paragraphs
* Bold and italic text
* Ordered and unordered lists
* Links
* Images
* Tables
* Blockquotes
* Code blocks
* Inline code
* Task lists
* Alerts
* Collapsible sections
* Other GFM features covered in the session

### Suggested Approach

Start with the **Getting Started** topic and build the documentation set in sequence:

```text
Getting Started
       ↓
Installation
       ↓
User Guide
       ↓
Administration
       ↓
Troubleshooting
```

Make sure the topics are connected using appropriate links and that the documentation is easy for a user to navigate.

## Project Goal

By completing this exercise, you will practice how to:

* Create Markdown documentation.
* Organize multiple topics into a documentation set.
* Use GitHub Flavored Markdown (GFM).
* Create links between documentation topics.
* Structure content for different user needs.
* Apply Markdown consistently across a documentation project.

**The objective is not just to write Markdown. It is to create a small, usable documentation project.**
